# 1 引言（Introduction）

## 1.1 编写目的（Purpose）

本软件需求规格说明书（SRS）旨在：

* 为开发团队提供统一、明确、可执行的需求基础；
* 为测试团队提供测试用例编写依据；
* 为项目干系人（产品设计师、项目管理者）提供需求确认材料；
* 作为后续设计文档（架构、数据库设计、接口设计）的技术基础。

本 SRS 描述了“声印（VoiceMark）”系统的功能、数据结构、性能要求、安全要求及运行环境规范。

---

## 1.2 背景（Background）

**项目名称**：声印（VoiceMark）

**项目定位**：
一个支持语音记录、语音 AI 解读建议、地理位置标注、可视化统计、内容分享的多端记录类 Web 应用。

**项目目标**

* 让用户方便地录制语音记录并进行结构化管理；
* 使用大语言模型（LLM）提供即时内容辅助理解、情绪分析或主题归纳（仅实时生成，不存储）；
* 提供地图标注、时间线、数据统计等能力；
* 支持评论、点赞、收藏、热门推荐等社交元素；
* 支持跨平台使用（Web + Android）。

**主要用户痛点**

* 现有录音笔 App 记录混乱，没有结构化管理能力；
* 心情记录/语音日记缺少理解辅助，用户难以整理；
* 无法跨地点管理不同的语音片段；
* 缺乏社交互动，如点赞、评论、热门趋势；
* 普通笔记类产品不适合语音主导的交互。

**目标用户**

* 喜欢语音记录的普通用户；
* 进行采访、调研的工作者；
* 需要情绪记录、随记的用户；
* 对 LLM 解读有需求的人群。

**开发团队**

由xxx等四人小组组成的开发团队，每个人并行的开发各自负责的功能模块，并且负责与边缘功能涉及到的两个或多个其他模块的负责人对模块对接进行交流

## 1.4 假定与约束（Assumptions & Constraints）

**业务约束**

* LLM 返回内容不持久化，仅作为即时建议
* 用户音频存储走对象存储（阿里云 OSS / MinIO）
* 音频文件最大 20 MB

**团队约束**

* 前后端并行迭代开发
* 采用 Git + CI（GitHub Actions 或 GitLab CI）
* 线上沟通使用QQ或者微信群聊


**开发期限**
* 预计开发1个半月，从2025年11月中旬起，至2026年1月初结束

## 1.5 用户特点（User Characteristics）

**普通用户**

* 年龄 16–45 岁
* 习惯使用手机与 PC 记录内容
* 对语音识别、AI 解读有兴趣
* 熟悉基础 Web 或手机移动端操作

**系统维护人员**

* 熟悉微服务架构、容器化部署
* 熟悉 Java、SQL、Redis、日志监控系统
* 能管理音频存储与地图 API 配置

# 2 功能需求（Functional Requirements）

## 2.1 系统范围（System Scope）

声印系统包含以下主要功能：

1. **用户与认证模块**
2. **音频记录管理模块**
3. **标签管理模块**
4. **位置记录与地图模块**
5. **评论 & 点赞模块**
6. **热门推荐与内容流模块**
7. **数据统计与可视化模块**
8. **LLM 实时辅助模块（仅实时生成，不存储）**

系统通过前端 Vue3 Web 页面及 Android 打包 App 提供服务。
后端采用 Spring Boot 微服务：

* Auth Service
* User Service
* Audio Service
* Social Service（评论/点赞）
* Notification Service（热门推荐）
* Sse Service
* UserPersona Service
* LLM Service

## 2.2 系统总体流程（Overall System Flow）

**文本描述流程：**

1. 用户通过账号注册/登录进入系统

4. 用户可选择标签、位置信息、描述信息
5. 用户查看他人记录，可评论、点赞
6. 系统自动更新热门内容排序与推荐权重

### **UC-01 用户注册（User Registration）**

**参与者：**
未注册用户

**前置条件：**
无

**后置条件：**
系统创建新的认证账号（AuthenticationAccount）与默认用户资料（UserProfile）

#### **基本流程：**

1. 用户打开注册页面。
2. 用户输入用户名、邮箱、手机号与密码。
3. 系统验证用户名长度、邮箱格式、手机号格式与密码合法性。
4. 系统检查用户名、邮箱、手机号是否已被使用。
5. 系统发送验证码邮件，用户手动验证。
6. 系统为用户创建 AuthenticationAccount。
7. 系统为新账号创建默认的 UserProfile。
8. 返回注册成功提示。

#### **异常流程：**

* 3a. 邮箱格式不合法 → 显示“邮箱格式错误”
* 3b. 手机号格式无效 → 显示“手机号格式错误”
* 3c. 密码不符合要求（过短/过弱） → 阻止提交，提示强度要求
* 3d. 用户名包含非法字符或长度超限 → 返回“用户名格式不正确”
* 4a. 邮箱已注册 → 返回“邮箱已被占用”
* 4b. 手机号已注册 → 返回“手机号已被占用”
* 4c. 用户名已存在 → 返回“用户名已被占用”
* 5a. 验证码未验证 → 流程暂停
* 6a. 创建 AuthenticationAccount 失败（数据库异常）
* 7a. 创建 UserProfile 失败 → 需要事务回滚
* 8a. 网络问题导致前端无法收到注册成功回执 → 允许用户刷新后查看登录状态

### **UC-02 用户登录 / JWT 认证（User Login）**

**参与者：**
已注册用户

**前置条件：**
已有有效账号

**后置条件：**
系统颁发 JWT（及可选的 Refresh Token）

#### **基本流程：**

1. 用户输入用户名/邮箱/手机号和密码。
2. 系统验证账号是否存在。
3. 系统比对密码哈希。
4. 验证通过后生成 JWT Token。
5. 用户成功登录，进入首页。

#### **分支事件流**：

* 找回密码：
1. 用户点击"忘记密码"。
2. 系统跳转至密码重置页面。
3. 用户输入邮箱/手机号申请重置。
4. 系统发送验证码或重置链接。
5. 用户验证身份后设置新密码。

#### **异常流程：**

* 2a. 账号不存在 → 返回“账号不存在”
* 3a. 密码错误 → 返回“密码不正确”
* 3b. 密码输错次数过多 → 锁定账号 X 分钟
* 4a. Token 生成失败（加密模块异常） → 返回“无法登录，请稍后重试”
* 4b. Redis/会话服务不可用 → 返回“系统繁忙”
* 5a. 账号被封禁 → 阻止登录
* 分支3a. 找回密码的账户不存在 → 提示“账户不存在”
* 分支5a. 验证码过期 → 提示“验证码已过期”

### **UC-04 录制音频 / 上传音频（Record or Upload Audio）**

**参与者：**
用户

**前置条件：**
用户已登录

**后置条件：**
音频文件上传成功并存储在对象存储中（未形成 AudioRecord 结构）。

#### **基本流程：**

1. 用户点击“录音/上传”按钮。
2. 系统请求地理位置定位权限
3. 用户填写标题、描述。
4. 用户可选择标签（多个）。
5. 用户可请求 LLM 生成音频建议（实时，不存储）。
6. 若录音模式，则系统请求麦克风权限并开始录音。
7. 用户停止录音。
8. 用户提交音频记录。
9. 前端上传记录到后端服务。

#### **扩展流程：**

* 录音结束后用户可继续：
  * 试听音频
  * 删除重新录制

#### **异常流程：**

* 2a. 用户拒绝 GPS 定位授权 → 拒绝用户录音或者上传音频
* 5a. LLM 请求失败 / 网络波动 → 返回“无法获取建议”
* 6a. 用户拒绝麦克风权限 → 无法录音，只能上传本地文件
* 6b. 录音过程中断（系统权限变更或浏览器中断）
* 8a. 上传记录失败（网络断开 / 文件过大 / 格式不支持）
* 8b. 提交时用户 Token 过期 → 强制重新登录
* 9a. 后端解析失败 → 返回“音频无法上传”
* 9b. 数据库存储失败 → 创建失败

### **UC-05 接收通知（Receive Notifications）**

**参与者**
1. 用户、管理员

**前置条件**
1. 用户已登录；有待处理的系统通知

**后置条件**
1. 用户查看系统通知，通知状态更新为已读

#### **基本流程**

1. 系统检测到有待发送的通知（如系统维护公告）。
2. 系统在用户页面右上角显示通知红点提示。
3. 用户点击通知图标进入通知中心。
4. 系统显示未读通知列表。
5. 用户点击某条通知查看详情。
6. 系统显示完整的通知内容及相关操作选项。
7. 系统将该通知标记为已读状态。

#### **分支事件流**

1. 批量处理通知：用户可批量标记通知为已读，或一键清空所有已读通知。
2. 通知静默：用户进入通知界面，选择"通知静默"，此后将不再提示有未读通知（红点消失）。

#### **异常流程**

* 4a. 通知内容异常 → 显示"通知内容暂不可用"
* 4b. 网络连接中断 → 提示"网络连接异常，通知同步暂停"
* 4c. 通知加载失败 → 提示"通知加载失败，请刷新页面重试"
* 6a. 音频详情加载失败 → 提示"音频加载失败，请刷新页面重试"

### 核心数据类列表

#### **AuthenticationAccount（认证账号）**
用于用户登录认证，保证系统识别唯一用户身份,存储用户登录相关信息，如用户名、邮箱、手机号和密码哈希

* UserId 主键，唯一标识一个用户账号，与 UserProfile 一对一。
* UserName 登录名称，必须唯一。
* Email 用户邮箱，用于登录和通知，唯一。
* PhoneNumber 用户手机号，用于登录或找回密码，唯一。
* PasswordHash 使用安全算法加密后的密码。
* RegisterTime 用户账号创建时间。

关系：

* 与 UserProfile 一对一关联（UserId 作为外键）
* 与 AudioRecord、Comment、Like、Favorite 间接关联，通过 UserId 表示操作或所有者

#### **UserProfile（个人信息）**
存储用户可编辑的个人信息，用于展示用户资料,与前端用户界面绑定，用于显示昵称、头像、简介等

* UserId 主键，与 AuthenticationAccount.UserId 相同。
* Nickname 用户昵称，用于展示
* AvatarUrl 用户头像地址。
* Bio 个人简介（短文本）。
* SelfDescription 更详细的个性描述（长文本）。

关系：

* 与 AuthenticationAccount 一对一
* 与 AudioRecord、Comment、Favorite 等一对多关系，表示用户创建的音频、评论及收藏

---

#### **AudioRecord**
存储用户上传或录制的音频文件及相关信息,支持关联位置、标签、评论、点赞、收藏

* RecordId 主键，唯一标识一条音频记录。
* UserId 上传该音频的用户Id。
* Title 音频标题。
* Description 音频的补充描述信息。
* AudioUrl 音频文件在对象存储中的访问地址。
* TranscriptText 音频转文本内容（如有语音识别模块）。
* Latitude 音频录制地点的纬度。
* Longitude 音频录制地点的经度。
* CreatedTime 记录创建时间。
* UpdatedTime 最近修改时间。

关系：

* 与 UserProfile 一对多（UserId）——创建者
* 与 Tag 多对多，通过 RecordTag 关联
* 与 Comment 一对多（RecordId）——评论所属记录
* 与 Like 一对多（TargetType=RECORD）——音频点赞
* 与 Favorite 一对多（RecordId）——用户收藏

---

#### **Tag**
对音频记录进行分类和标记，支持筛选与搜索,支持用户自定义标签或系统推荐标签

* Name 标签名称，如“自然声”“城市环境”等。
* RecordId 指向一条音频记录。

关系：

* 与 AudioRecord 多对多
* 不直接与用户关联，关联行为通过 Tag 和 AudioRecord 间接体现

---

#### **Comment**
用户对音频记录的评论，可支持回复其他评论形成多级评论,用于互动模块，如点赞、通知

* CommentId 主键，唯一标识一条评论。
* RecordId 评论所属的音频记录。
* UserId 评论者用户。
* ParentCommentId (nullable) 父级评论 ID，为空时表示一级评论。
* Content 评论内容文本。
* CreatedTime 评论的发布时间。

关系：

* RecordId → AudioRecord.RecordId
* UserId → UserProfile.UserId（评论者）
* ParentCommentId → Comment.CommentId（父评论，用于多级嵌套）
* 与 Like 一对多关系（TargetType=COMMENT）——评论点赞

---

#### **Like**
用户对音频或评论的点赞行为记录,支持计算热门推荐、互动统计

* LikeId 主键，唯一标识一条点赞记录。
* UserId 点赞的用户。
* TargetType（Enum: RECORD / COMMENT） 枚举：RECORD / COMMENT，用于区分点赞对象类型。
* TargetId 对应的 RecordId 或 CommentId。

关系：

* UserId → UserProfile.UserId（点赞者）
* TargetType + TargetId → AudioRecord.RecordId 或 Comment.CommentId
* 通过 TargetId 与目标对象绑定

---

#### **Favorite**
用户收藏音频记录, 支持查看收藏列表、跳转至地图展示音频地点

* FavoriteId 主键，唯一标识一条收藏行为。
* UserId 收藏者用户。
* RecordId 被收藏的音频记录 ID。
* CreatedAt 收藏时间。

关系：

* UserId → UserProfile.UserId（收藏者）
* RecordId → AudioRecord.RecordId（被收藏记录）

#### **Notification**  
用户接收系统或他人互动产生的通知，支持按类型分类查看、标记已读/未读，并可跳转至关联的音频记录或评论。

* id 主键，唯一标识一条通知。  
* actorUserId 触发通知的用户 ID（如点赞、评论的用户）。  
* receiverUserId 接收通知的用户 ID。  
* type 通知类型（如“新评论”、“被点赞”、“被收藏”等）。  
* targetId 通知所指向的目标对象 ID（如音频记录 ID 或评论 ID）。  
* targetType 目标类型，枚举值（如 RECORD 表示音频记录，COMMENT 表示评论）。  
* eventId 唯一事件 ID，用于去重或幂等处理。  
* content 通知内容摘要，用于前端展示（如“张三评论了你的音频”）。  
* createdAt 通知创建时间。  
* isRead 是否已读，用于控制未读红点等交互状态。

关系：

* actorUserId\receiverId → UserProfile.UserId
* targetId → Favorite.FavoriteId\Comment.CommentId\Like.LikeId

### **2.3.3.1 状态图（State Machine Descriptions）**

#### **（1）用户状态（User）**

**描述：**
用户对象在系统中的状态主要包括：

1. **未注册（Unregistered）**：用户尚未创建账户，可访问注册页面。
2. **已注册（Registered）**：账户已创建，但未登录状态。
3. **已登录（Logged In）**：用户已验证身份，可执行系统所有操作。
4. **已登出（Logged Out）**：用户主动退出登录后的状态。
5. **账号被封禁/禁用（Suspended/Disabled）**：账户因违规或系统限制被禁止使用。

**状态转移逻辑：**

* 未注册 → 注册成功 → 已注册
* 已注册 → 登录成功 → 已登录
* 已登录 → 用户主动退出 → 已登出
* 已注册/已登录 → 系统封禁 → 禁用
* 禁用 → 系统解封 → 已注册或已登录

**说明：**
用户状态决定可操作的系统功能，如登录状态才能创建音频记录、评论、点赞、收藏等。

# **3 非功能需求（Non-functional Requirements）**

本节描述系统在性能、安全、灵活性、可维护性等方面的要求，用以确保系统稳定、可靠、易扩展，便于开发团队进行设计和实现。

---

## **3.1 性能要求（Performance Requirements）**

### **3.1.1 精度（Accuracy / Precision）**

* **GPS 精度**：系统中所有音频记录位置需保留经纬度 6 位小数（约 0.11 米精度），保证地图定位与附近记录查询精确。
* **音频转文本精度**：依赖第三方语音识别 API，要求普通话语音的文字识别正确率大于 90%，并尽量减少语义错误和断句错误。
* **LLM 辅助建议精度**：返回的音频主题分类、标题建议、情感倾向等结果，应尽量符合实际音频内容，保证用户可直接参考。
* **UI 显示精度**：地图显示、列表排序、热门推荐分数等应保持小数点后一位显示，避免四舍五入引起排名误差。

---

### **3.1.2 响应时间（Response Time / Latency）**

* **用户认证**：登录操作 ≤ 2 秒（包括前端提交、后端校验和 JWT 生成）。
* **首页加载**：热门推荐列表加载 ≤ 3 秒，保证用户访问首页时流畅。
* **音频上传**：单条音频（<50MB）上传至对象存储总时长 ≤ 8 秒，包括网络传输时间。
* **地图附近内容查询**：根据 GPS 坐标查询半径范围内记录，返回结果 ≤ 5 秒。
* **LLM 请求**：调用 LLM API 返回建议 ≤ 5 秒，以保证用户实时创建音频记录时体验顺畅。
* **操作反馈**：所有 CRUD 操作（创建/修改/删除记录、评论、收藏、点赞等）界面反馈 ≤ 2 秒。

**说明：** 系统应通过前端异步加载、后台缓存以及分页查询等技术优化响应速度。

---

### **3.1.3 输入/输出要求（I/O Requirements）**

#### **输入内容（Input）**

1. **音频文件**

   * **媒体格式**：MP3、WAV
   * **文件大小**：单条音频 ≤ 50MB，避免过大导致上传/存储延迟
   * **时长范围**：建议 5 秒–5 分钟
   * **录制精度**：采样率 ≥ 16 kHz，保证语音清晰
   * **示例**：用户录制一段 30 秒的普通话音频，保存为 WAV 格式，文件大小 2MB

2. **文本内容**

   * **类型**：用户输入的标题、描述、评论内容、标签文本
   * **编码**：UTF-8
   * **长度限制**：

     * 标题 ≤ 50 个字符
     * 描述 ≤ 500 个字符
     * 评论 ≤ 200 个字符
   * **校验要求**：禁止 HTML/JS 注入，禁止空文本提交
   * **示例**：用户为音频记录填写标题“埃菲尔铁塔夜景”，描述“傍晚拍摄的塔身灯光，微风轻拂”，UTF-8 编码

3. **GPS 经纬度**

   * **类型**：浮点数
   * **精度**：保留 6 位小数（约 0.11 米）
   * **范围**：

     * 纬度：-90 ~ +90
     * 经度：-180 ~ +180
   * **示例**：用户当前位置 48.858844, 2.294351（埃菲尔铁塔坐标）

4. **标签（Tag）**

   * **类型**：字符串
   * **长度**：≤ 20 个字符
   * **字符集**：支持中文、英文、数字
   * **规则**：禁止重复标签，自动去重
   * **示例**：用户为音频记录添加标签“旅行”“夜景”“巴黎”

---

#### **输出内容（Output）**

1. **JSON 数据**

   * **用户信息**：UserId、Nickname、AvatarUrl、注册时间
   * **音频记录**：RecordId、Title、Description、AudioUrl、TranscriptText、Tags、Latitude、Longitude、CreatedTime、UpdatedTime
   * **评论/点赞/收藏**：CommentId、UserId、Content、LikeCount、FavoriteCount
   * **推荐数据**：热门分数、排序权重、推荐算法标识
   * **示例**：

   ```json
   {
       "RecordId": "1001",
       "Title": "埃菲尔铁塔夜景",
       "AudioUrl": "https://oss.example.com/audio/1001.wav",
       "TranscriptText": "傍晚的埃菲尔铁塔，灯光璀璨...",
       "Tags": ["旅行", "夜景", "巴黎"],
       "Latitude": 48.858844,
       "Longitude": 2.294351,
       "CreatedTime": "2025-11-30T18:00:00Z",
       "UpdatedTime": "2025-11-30T18:05:00Z"
   }
   ```

2. **状态与错误反馈**

   * **HTTP 状态码**：200、201、400、401、403、404、500
   * **错误信息**：JSON 格式，包含 `code`、`message`
   * **示例**：

   ```json
   {
       "code": 400,
       "message": "音频文件大小超过限制 50MB"
   }
   ```

---

#### **输入输出校验与异常处理**

* 对输入进行格式和大小验证，超出限制或非法格式直接返回错误
* GPS 无效 → 返回错误，提示用户检查定位权限
* 音频上传失败 → 返回 HTTP 500 错误，并可重试
* 标签或文本为空 → 返回 400，提示用户填写必填字段
* 图片格式不合法或过大 → 返回 400，禁止上传

---

## **3.2 数据管理能力（Data Management Requirements）**

* **用户规模预测**：初期 1,000 用户，三年内预估约 30,000 用户。
* **数据生成速率**：每用户每天约 1–3 条音频记录。
* **音频存储**：对象存储容量 1–3 TB，支持横向扩展。
* **数据库设计**：采用 MySQL / PostgreSQL 分库分表策略，保证查询性能。
* **缓存策略**：Redis 用于存储热门权重、推荐分数，TTL 1–5 分钟，可快速响应热点数据。
* **备份与恢复**：

  * 冷备每日一次
  * 热备实时同步，保证关键数据可快速恢复
  * 音频文件与数据库分开备份，支持灾难恢复

**说明：** 数据管理方案保证系统在用户量增长和高并发下仍能稳定运行。

---

## **3.3 安全要求（Security Requirements）**

* **用户认证**：

  * 密码使用 bcrypt 哈希算法存储
  * JWT + Refresh Token 管理会话，保证安全访问
* **数据传输**：HTTPS 全站加密，保证通信安全
* **输入校验**：防止 SQL 注入、XSS、CSRF 攻击
* **访问控制**：用户只能操作自己权限范围内的资源
* **日志审计**：记录用户操作、异常事件，便于安全监控
* **API 限流**：防止恶意刷接口和 DDoS 攻击
* **异常处理**：系统错误或外部 API 异常需安全捕获，并提供友好提示

---

## **3.4 灵活性（Flexibility / Extensibility）**

* 推荐系统算法可切换，包括简单加权评分、行为学习排序等
* 标签系统可扩展，支持新分类、合并或删除标签
* 音频识别和 LLM 服务可替换供应商，接口统一规范化
* 系统微服务化设计，可独立升级单个模块，不影响整体运行

---

## **3.5 其他专门要求（Other Requirements）**

* **可维护性**：代码分层明确（Controller-Service-DAO），微服务模块化
* **扩展性**：中间件可替换（如 MinIO ↔ 阿里云 OSS、Redis ↔ Memcached）
* **UI/UX**：支持深色模式、适配不同屏幕尺寸和分辨率
* **异常处理提示**：操作失败时提供清晰提示与恢复建议

# **4 运行环境规定（Operating Environment Requirements）**

## **4.1 设备要求（Hardware Requirements）**

* **移动端**：Android 8.0+，CPU 多核 ≥1.8GHz，RAM ≥4GB
* **PC 端**：Windows / macOS / Linux，Chrome 或 Edge 浏览器最新稳定版
* **必备外设**：

  * 麦克风（录音功能）
  * GPS 定位权限（地图与附近记录功能）
* **网络要求**：Wi-Fi 或 4G/5G 网络，保证音频上传与 API 调用稳定

---

## **4.2 支持软件（Software Requirements）**

* **前端开发**：Node.js 18+，Vue3 框架，Webpack / Vite 打包
* **后端开发**：JDK 17、Spring Boot 3.x、微服务架构
* **数据库**：MySQL 8.0，Redis 6+ 用于缓存和热点数据
* **容器化与部署**：Docker CE，Kubernetes（可选）
* **测试工具**：Postman、Jest、JUnit
* **版本管理**：Git

---

## **4.3 外部接口（External Interfaces）**

* **语音识别 API**：用于音频转文本、生成摘要与关键词
* **LLM 服务**：生成音频标题、情感分析、主题建议（如 OpenAI / DeepSeek）
* **地图 API**：高德地图 / 百度地图，支持地图显示、附近记录查询
* **对象存储 API**：阿里云 OSS / MinIO，用于音频文件存储和访问
* **通信协议与数据格式**：HTTP/HTTPS + JSON；接口返回统一格式，便于前端解析
