## 2	系统软件体系结构

后端系统采用微服务架构，每个子系统作为独立的微服务运行，彼此通过API进行通信。各子系统内部通过类和接口实现功能模块的调用和数据处理。

软件体系采用分层架构，设计如下：

表现层由 HTML、CSS 和 Vue 构建的 Web 页面组成，负责与用户进行交互。用户通过浏览器访问这些页面，进行各种操作，如查看账户信息、上传音频、进行社交互动等。

网络层通过 HTTP 协议进行通信，确保数据在网络上传输的安全性。Spring Cloud Gateway 用于请求路由和认证，确保请求被正确地转发到相应的服务，并进行必要的身份验证。

服务层包含多个子系统，每个子系统作为独立的微服务运行，处理特定的业务逻辑。这些子系统包括认证服务、用户服务、音频服务、社交服务、通知服务、SSE服务、LLM服务和用户画像服务等。微服务架构使得各个子系统可以独立开发、部署和扩展，提高了系统的灵活性和可维护性。

数据层使用 MySQL 数据库进行数据存储和管理，确保数据的持久性和一致性。数据库为各个微服务提供数据支持，满足系统的业务需求。

## 3	子系统设计

### 3.1	子系统描述

#### 3.1.1  登录子系统

登录子系统负责对用户的登录操作进行管理，并且为用户提供注册、找回密码等操作。

#### 3.1.2  用户信息子系统

用户信息子系统用于对用户个人信息进行管理，包括用户资料、收藏、设置等功能。

#### 3.1.3  音频管理子系统

音频管理子系统负责音频的上传、发布、查询、删除等操作，支持音频文件的管理和地理位置关联。

#### 3.1.4  社交行为子系统

社交行为子系统负责用户之间的社交互动，包括评论、回复、点赞等功能。

#### 3.1.5  通知子系统

通知子系统负责向用户推送各种通知信息，包括评论通知、点赞通知等。

#### 3.1.6  SSE推送子系统

SSE推送子系统负责建立服务器与客户端之间的长连接，实现实时推送通知功能。

#### 3.1.7  LLM子系统

LLM子系统负责调用外部LLM API，为用户提供智能建议和推荐功能。

#### 3.1.8  用户画像子系统

用户画像子系统负责根据用户行为生成和维护用户画像，用于个性化推荐。

### 3.2	微服务

#### 3.2.1  账户微服务

账户子系统包含于账户微服务（AuthService），包含以下设计类：

**（1）业务类（Service）：**

- AuthService：用户认证服务接口，定义用户注册、登录、登出、找回密码等业务方法
- EmailService：邮件发送服务接口，定义发送邮件的方法
- AuthServiceImpl：AuthService的实现类，实现用户认证相关业务逻辑
- EmailServiceImpl：EmailService的实现类，实现邮件发送业务逻辑

**（2）实体类（Entity）：**

- User：用户实体类，对应数据库users表，包含用户ID、用户名、密码、邮箱、手机号、注册时间等属性

**（3）DTO类（数据传输对象）：**

- UserLoginRequestDTO：用户登录请求DTO，包含用户名和密码
- UserRegisterRequestDTO：用户注册请求DTO，包含用户名、密码、邮箱、手机号、验证码
- RegisterCodeRequestDTO：注册验证码请求DTO，包含邮箱
- PasswordResetInitRequestDTO：密码重置初始化请求DTO，包含用户标识（邮箱或手机号）
- PasswordResetRequestDTO：密码重置请求DTO，包含验证码和新密码
- PasswordChangeRequestDTO：密码修改请求DTO，包含旧密码和新密码
- LoginResponseDTO：登录响应DTO，包含token和用户名
- UserResponseDTO：用户响应DTO，包含用户基本信息

**（4）控制器类（Controller）：**

- AuthController：认证控制器，处理用户注册、登录、登出、找回密码等HTTP请求

#### 3.2.2  用户信息微服务

用户信息子系统包含于用户信息微服务（UserService），包含以下设计类：

**（1）业务类（Service）：**

- UserService：用户信息服务接口，定义用户资料管理、收藏管理、设置管理等业务方法
- UserServiceImpl：UserService的实现类，实现用户信息相关业务逻辑

**（2）实体类（Entity）：**

- UserProfile：用户资料实体类，对应数据库user_profiles表，包含用户ID、昵称、头像URL、个人简介、详细描述等属性
- UserSetting：用户设置实体类，对应数据库user_settings表，包含用户ID、设置项等属性

**（3）DTO类（数据传输对象）：**

- UserProfileDTO：用户资料DTO，包含用户ID、昵称、头像URL、个人简介、详细描述等信息
- UserProfileUpdateRequestDTO：用户资料更新请求DTO，包含昵称、个人简介、详细描述等信息
- UserSettingDTO：用户设置DTO，包含用户设置信息

**（4）控制器类（Controller）：**

- UserController：用户控制器，处理用户资料查询、更新、收藏管理、设置管理等HTTP请求

#### 3.2.3  音频管理微服务

音频管理子系统包含于音频微服务（AudioService），包含以下设计类：

**（1）业务类（Service）：**

- AudioService：音频服务接口，定义音频上传、发布、查询、删除等业务方法
- StorageService：存储服务接口，定义文件上传、删除等方法
- AudioServiceImpl：AudioService的实现类，实现音频管理相关业务逻辑
- RemoteStorageServiceImpl：StorageService的远程存储实现类，实现远程文件存储

**（2）实体类（Entity）：**

- Audio：音频实体类，对应数据库audios表，包含音频ID、用户ID、音频URL、图片URL、纬度、经度、标题、描述、标签集合、上传时间、发布时间、状态、删除标志、访问次数等属性

**（3）DTO类（数据传输对象）：**

- AudioResponseDto：音频响应DTO，包含音频ID、用户ID、用户名、音频URL、图片URL、纬度、经度、标题、描述、标签集合、上传时间、发布时间、状态、访问次数等信息
- UploadAudioRequest：音频上传请求DTO，包含纬度和经度信息
- PublishAudioRequest：音频发布请求DTO，包含标题、描述、标签集合、图片URL、是否公开等信息
- UpdateAudioRequest：音频更新请求DTO，包含需要更新的音频信息

**（4）控制器类（Controller）：**

- AudioController：音频控制器，处理音频上传、发布、查询、删除、更新等HTTP请求

**（2）实体类（Entity）：**

### 3.3	接口

在接口设计上，为了确保微服务的隔离性和解耦，直接在每个微服务内部定义所需的数据结构，在涉及其他子系统的实体类时就地构造数据结构，并从数据库读取相应信息。

其中，通知子系统、Sse子系统和用户画像子系统采取事件驱动，统一经由公共组件驱动，不涉及直接交互。

#### 4.1.2  UserRepository

UserRepository用于实现对User实体对应的数据库表的操作。通过继承Spring Data JPA提供的JpaRepository接口，UserRepository无需手动编写基础的增删改查SQL方法，即可完成对User表的查询、插入、更新和删除等操作，极大地提高了开发效率。

主要方法包括：
- findByUsername(String username)：根据用户名查找用户
- existsByUsername(String username)：检查用户名是否存在
- existsByEmail(String email)：检查邮箱是否存在
- existsByPhoneNumber(String phoneNumber)：检查手机号是否存在
- findByPhoneNumber(String phoneNumber)：根据手机号查找用户
- findByEmail(String email)：根据邮箱查找用户

#### 4.1.3  AuthServiceImpl业务逻辑类

（1）`ApiResponse<Void> sendRegisterCode(String email)`

发送注册验证码，主要实现验证邮箱格式，检查邮箱是否已被注册，生成6位验证码并存储到Redis，设置5分钟过期时间，调用EmailService发送验证码邮件。

（2）`ApiResponse<Void> register(UserRegisterRequestDTO dto)`

用户注册，主要实现检查用户名、邮箱、手机号是否已存在，验证注册验证码，对密码进行加密，创建用户账户并保存到数据库，创建默认用户资料，删除Redis中的验证码。

（3）`ApiResponse<LoginResponseDTO> login(UserLoginRequestDTO dto)`

用户登录，主要实现根据用户名查找用户，验证密码是否正确，生成JWT token，返回包含token和用户名的登录响应。

（4）`ApiResponse<UserResponseDTO> getCurrentUser(HttpServletRequest request)`

获取当前登录用户信息，主要实现从请求中提取JWT token，解析用户ID，查询用户信息，返回用户响应DTO。

（5）`ApiResponse<Void> logout(HttpServletRequest request)`

用户登出，主要实现清除用户会话信息，返回登出结果。

（6）`ApiResponse<Void> requestPasswordReset(String identifier)`

请求密码重置，主要实现验证用户标识（邮箱或手机号），查找用户，生成重置验证码并存储到Redis，调用EmailService发送重置邮件。

（7）`ApiResponse<Void> resetPassword(PasswordResetRequestDTO dto)`

重置密码，主要实现验证重置验证码，对新密码进行加密，更新用户密码，删除Redis中的验证码。

#### 4.1.4  AuthController控制类

提供了以下前后端接口：

（1）发送注册验证码

请求方式：POST

请求路径：/api/auth/register/code

参数示例：{"email": "user@example.com"}

返回：`ApiResponse<Void>`

（2）用户注册

请求方式：POST

请求路径：/api/auth/register

参数示例：{"username": "testuser", "password": "password123", "email": "user@example.com", "phoneNumber": "13800138000", "code": "123456"}

返回：`ApiResponse<Void>`

（3）用户登录

请求方式：POST

请求路径：/api/auth/login

参数示例：{"username": "testuser", "password": "password123"}

返回：`ApiResponse<LoginResponseDTO>`，包含token和用户名

（4）获取当前用户信息

请求方式：GET

请求路径：/api/auth/me

参数：从请求头中获取JWT token

返回：`ApiResponse<UserResponseDTO>`

（5）用户登出

请求方式：POST

请求路径：/api/auth/logout

参数：从请求头中获取JWT token

返回：`ApiResponse<Void>`

（6）请求密码重置

请求方式：POST

请求路径：/api/auth/password/reset-request

参数示例：{"identifier": "user@example.com"}

返回：`ApiResponse<Void>`

（7）重置密码

请求方式：POST

请求路径：/api/auth/password/reset

参数示例：{"identifier": "user@example.com", "code": "123456", "newPassword": "newpassword123"}

返回：`ApiResponse<Void>`

### 4.8  用户画像微服务

#### 4.8.1  UserPersonaEntity实体类

| 属性名 | 类型 | 说明 |
|--------|------|------|
| userId | Long | 用户ID，主键 |
| personaData | String | 用户画像数据，JSON格式存储 |

#### 4.8.2  UserPersonaRepository

UserPersonaRepository用于实现对UserPersonaEntity实体对应的数据库表的操作。通过继承Spring Data JPA提供的JpaRepository接口，提供基本的CRUD操作。

#### 4.8.3  UserPersonaServiceImpl业务逻辑类

（1）`void handleEvent(UserBehaviorSignalEvent event)`

处理用户行为事件，更新用户画像，主要实现从事件中提取用户ID和行为信息，查询或创建用户画像，调用UserPersonaUpdateService更新画像，调用UserPersonaDecayService进行衰减处理，保存用户画像。

#### 4.8.4  UserPersonaUpdateServiceImpl业务逻辑类

（1）`void update(UserBehaviorSignalEvent event, UserPersona persona)`

根据用户行为事件更新用户画像，主要实现根据事件类型和行为信息，更新用户画像的相关字段，如兴趣标签、行为偏好等。

#### 4.8.5  UserPersonaDecayServiceImpl业务逻辑类

（1）`void decay(UserPersona persona)`

对用户画像进行衰减处理，主要实现根据衰减算法，对用户画像中的相关字段进行衰减处理，降低旧行为的影响权重。

#### 4.8.6  用户画像子系统控制器

用户画像子系统主要通过事件驱动方式工作，不直接提供HTTP接口，通过监听用户行为事件自动更新用户画像。
